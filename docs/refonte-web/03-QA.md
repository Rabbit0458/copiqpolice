> Limite de mesure : le volet navigateur de l'environnement était masqué
> (`document.hidden === true`), ce qui suspend `requestAnimationFrame`. Les

> serveur de développement : 24 blocs `.cq-reveal`, révélés progressivement à
> mesure de l'entrée dans le viewport.

en remontant l'arbre, ratio comparé au seuil (4,5:1, ou 3:1 pour le grand

Corrections appliquées à la suite de cet audit :

## 5. Points de rupture

Testés réellement, pas simulés par redimensionnement approximatif.

| Largeur | Résultat |
|---|---|
| 320 px | aucun défilement horizontal ; hero en une colonne ; titre sur 3 lignes ; échelle d'affichage abaissée à `clamp(2.1rem, 7vw, 5.25rem)` après constat |
| 375 / 390 / 430 px | mise en page identique au 320, plus confortable |
| 768 px (tablette) | parcours sur 2 colonnes, tarifs sur 2 colonnes |
| 1440 px | composition hero à 3 plans, tarifs sur 4 colonnes, bandes pleine largeur |

Sur mobile, la superposition du hero est abandonnée au profit d'un seul
panneau, et le tableau comparatif des tarifs devient une liste de cartes — pas
un tableau compressé.

## 6. Accessibilité

- un seul `<h1>` par page (vérifié sur `/`, `/tarifs`, `/ressources`,
  `/preparation/*`, `/faq`, `/404`) ;
- lien d'évitement `.cq-skip` + `<main id="contenu">` sur la vitrine et les
  pages publiques ;
- FAQ en `<details>`/`<summary>` natifs : navigable au clavier sans JavaScript ;
- focus visible unique (`outline: 2px solid #4D82FF`), déclaré hors `@layer`
  pour qu'aucun utilitaire ne le supprime ;
- cibles tactiles : `.cq-tap` impose 44 × 44 px sur tous les CTA ;
- `prefers-reduced-motion` neutralise reveals, flottements, dérives et
  animations de barres, en `!important` et hors layer ;
- `<noscript>` rend les sections visibles si le JavaScript ne se charge pas ;
- listes de définition (`dl`/`dt`/`dd`) pour les chiffres, sans doublon pour
  les lecteurs d'écran ;
- toutes les images portent un `alt` décrivant le sujet ; les images purement
  décoratives ont `alt=""` et `aria-hidden`.

## 9. Sécurité

- aucun secret dans `fae16dc1/` : recherche de `service_role`, `sk_live`,
  `sk_test`, `whsec_` → seule occurrence dans `SECURITY.md`, qui **nomme** ces
  variables sans en donner la valeur ;
- `copiq-config.js` ne contient que l'URL Supabase, la clé anon et l'URL du site ;
- les documents de livraison (`*.md`) sont présents dans le dossier FTP mais
  rendus inaccessibles en HTTP par une règle `.htaccess` : ils décrivent
  l'architecture, ils n'ont pas à être servis aux visiteurs ;
- la CSP n'a eu besoin d'**aucun** assouplissement.

## 10. Ce qui n'a pas été testé, et pourquoi

| Non testé | Raison |
|---|---|
| Parcours authentifié complet (dashboard, quiz, cas pratique, forum) | aucun compte de test fourni ; l'authentification n'a pas été modifiée |
| Paiement Stripe de bout en bout | nécessite une clé Stripe et un compte ; le chemin de paiement n'a pas été modifié |
| Test multi-sessions simultanées (§35) | nécessite des comptes de test ; à ne pas lancer sur la production sans autorisation explicite |
| Lighthouse (§48) | non disponible dans cet environnement ; les leviers habituels sont en place (export statique, police auto-hébergée, `lazy` hors hero, `width`/`height` sur toutes les images, aucune bibliothèque d'animation ajoutée) — à mesurer après mise en ligne |
| Rendu Safari / Firefox / iOS | un seul moteur disponible ici |
